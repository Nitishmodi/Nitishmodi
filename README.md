### Cimpress Technology — Software Engineer

Bengaluru, remote · since January 2025

Most of the work is on fulfillment: finding a shipment, correcting an address, creating or replanning a shipment, and getting a label onto a device on the floor.

I built a React and TypeScript console that puts shipment lookup, the operational context around that shipment, and address correction in one place. Daily escalations from that path dropped by about 90%. On the API side I wrote Node.js, Koa, and TypeScript services for shipment creation and replanning, and moved TMSv2 workflows onto Planman v2, which cut replanning time by about 35%.

The packing-slip service handles on the order of 50,000 documents a day. Work on that path reduced generation latency by about 40% and fulfillment errors by about 30%. Label delivery to iPack devices goes out over TCP from AWS Lambda, with SNS, SQS, and VPC peering, and retries bring delivery success to about 99.5%. A schema mismatch was showing up on about 20% of shipment integrations; fixing that, and watching the lifecycle in New Relic, made production failures easier to trace.

## Selected projects

### [SaaSquatch Lead Scorer](https://github.com/Nitishmodi/saasquatch-lead-scorer)

[Live demo](https://saasquatch-lead-scorer.vercel.app/) · [Walkthrough](https://www.loom.com/share/d24d7aaefaf5471a86ab6845ce8d2cde)

An acquisition search already returns hundreds of companies. The missing step is which owner to call first. This app takes an industry and a city, or a list you already have, and returns a ranked list with a reason for every point.

Discovery uses OpenStreetMap. Chains, branded locations, and directory or social links are filtered out. You can also paste URLs, upload a CSV, or drop a file in. The website column is detected, and URL variants collapse to one root domain.

Verification reads the live site. Emails and phone numbers are pulled from the pages, phones are validated, the email domain is checked for an MX record, and company age comes from the RDAP registration date. Sites blocked by robots.txt, stuck behind a CAPTCHA, or simply offline stay in the list with a next step, instead of vanishing.

The score is a rules engine, computed when the row is read and never stored, so the weights can change without another crawl. Age, owner-operated signals, a working email domain, a direct phone, a LinkedIn company page, and a stale website each add points. Hot is 65 and above, warm is 40 and above, and the rest is cold. Each row also gets a next action: email the owner, call, try LinkedIn, research, or skip. An opener is drafted for the email path, with a template if the model call is unavailable, and the export is a filtered CSV with HubSpot column names.

The client is Next.js and React. Enrichment runs in batches of five so the first leads are usable quickly. A cache in Turso keeps a crawl for seven days. A miss crawls the site, checks RDAP and DNS, writes the opener, then scores.

### [FlowPilot AI](https://github.com/Nitishmodi/FlowPilot--AI)

[Live demo](https://flow-pilot-ai-nu.vercel.app/)

A pnpm workspace for the checks that should happen before a pull request, run from the terminal or from the editor, on the repository in front of you. The apps are a CLI, a VS Code extension, and a small web guide. Shared packages cover config, process execution, git inspection, report formatting, the tools themselves, shared types, and the workflow runner.

`flowpilot.yml` is the contract. The default pre-PR workflow runs six steps in order: format, lint, types, tests, a scan of changed lines for likely credentials, and a review pass over added lines. The CLI also reports the branch and working tree, maps the repository from the files that are there, summarizes the diff against the base branch, explains a file from its exports, flags exports nothing else mentions, runs the package manager's own audit, and reads the last saved report when a step failed. `flowpilot pr` writes a pull request draft and does not open it unless creation is explicitly allowed. `task`, `resume`, and `handoff` keep a local note of what you were doing, the branch, and the changed files.

Results stay on the machine. The website cannot see the folder you linked. The repository's own GitHub Actions workflow installs with pnpm, typechecks, runs the tests, and builds the web app.

### [DevPilot AI](https://github.com/Nitishmodi/DevPilot-AI)

[Live demo](https://ai-interview-app-pink.vercel.app/)

A hiring screen with two desks. A recruiter writes a job post and chooses when it is visible. A candidate sees open roles ranked against the role they want, their experience, and their skills. Applying starts a screen written for that person: 20 skill questions, 5 recorded answers, and 5 communication answers. The answers are stored and scored. Both sides see the same scorecard, with charts and a PDF.

A proceed means above 80% in every section and above 80% overall. Anything short of that is marked not this time, and the candidate can be considered for a later role. The recruiter still makes the call.

The app is Next.js, React, and Tailwind, with Gemini for the screen and PostgreSQL through Drizzle for the data. An attempt, its job, the candidate, and the scorecard are read in one join. Saving an answer checks ownership without loading the whole paper. Job lists return a short preview, and screen counts are aggregated in SQL.
